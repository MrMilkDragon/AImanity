# 界面文案与布局

从用户在这个窗口要做的动作开始。在真实界面上标出入口、可编辑值、提交动作和反馈，再逐句问：删去这句，用户会失去哪项信息？说不出具体影响的句子直接删去。

### 文案取舍

| 界面上的内容 | 处理方式 |
| --- | --- |
| 标题「工作文件」，下方「在这里轻松管理你的所有工作文件」 | 保留标题和文件列表，删除副标题。 |
| 输入框「项目名称」，下方「请在上方输入项目名称」 | 用可见字段名关联输入框，删除重复提示。 |
| 「开启流畅的智能创作之旅」 | 删除。若这里需要一个操作，只写实际动作，如「新建文档」。 |
| 「上传失败」 | 有实际原因时写成「文件超过 20 MB」；可重试时把「重试」放在原处。 |
| 「向 3 位成员发送」 | 保留可核对的对象和范围。图标按钮提供可访问名称和键盘焦点。 |

### 按照同一条线布局

1. 先在屏上画出内容左、右边线，再排标题、列表首列、最后一个动作和输入区。量文本墨迹的起点、行基线和图标的可见中心，容器等宽有时仍会显得歪。
2. 同一行里的输入框、下拉框和主要按钮共用控件高度和标签基线。图标可以小，点击区域保持完整。文件表头和每行共用同一组列宽，名称可截断，单位与数值不可拆行。
3. 每组设一个标题层级。标题用字重和组间距建立层次，正文用正常字号；淡灰小字只承载确实需要的次要信息。先借用项目已有的字阶、边距、圆角与颜色。
4. AImanity 工作台两端留 24 个逻辑像素。表单行 40、紧凑操作 36、工具区 32；浮窗标题 15/22、区标题 14/20。玻璃填充约 35%，在实际背景上检查正文可读性。其他产品沿用自身设计系统的数值。
5. 就地浮窗以触发控件为锚点；切换入口时收起旧窗。展开、返回和关闭沿同一条路径，尊重减少动效设置。表单失败时让焦点和已填内容留在原处。

### 成品检查

在普通窗口和最短支持窗口各走一次主要操作。再用长译文、从右向左的文字以及键盘走同一条路径。检查首末边线、基线、主次字重、单位换行和操作结果可见性。交付时给出所删的一条原文、保留的一项必要信息和实际改正的一处布局。
