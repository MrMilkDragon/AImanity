# 0.0.5 Europium · 应用场景与训练计划

Europium 优先验证 Agent 能否认清消息来源、跟上用户中途的改口，并交付能在原应用打开的文件。训练产物是实际应用的操作指引、可重做的任务和能核对的结果。切换模型后可用同一任务复测。

## 场景与优先顺序

| 优先级 | 触发与任务 | 需要专门练的判断 | 验收时看什么 |
| --- | --- | --- | --- |
| 首批 | 手机收到物料、报价或报名清单，在电脑核对后回传 | 找到下载原件、识别列、分清数量与差额、保留可编辑公式 | 重开最终工作簿，核对公式和数值。手机与工作文件中的成品一致 |
| 首批 | 微信、企微或钉钉收到改稿，附件里既有原稿又有新版本 | 识别来源会话和指定版本，电脑修改后回到同一会话 | 原稿保留，改稿可打开，唯一一次外发附件出现在正确会话 |
| 首批 | Copilot 改演示稿，用户先说“全部改蓝”，马上纠正“只改第 3 页” | 区分选中的文本框与整页，按最新范围修正已执行部分 | 重新打开演示稿检查第 3 页，其他页与原稿一致，只交付最终版 |
| 下一批 | 两个群同时要求排班和补物料，用户又插入一条语音指令 | 按来源分开待办，语音先行，切回原任务时恢复文件和收件人 | 按正确顺序完成，两份结果各归原会话。重开时只续做未完成步骤 |
| 下一批 | 到货照片、装箱单与现场缺件需要交班 | 从图中提取可读的型号与件数，将未看清的项目留待核实 | 台账每项能回到其原图，数量差异和未核实项分开 |
| 下一批 | 培训群发来视频和说明，委托制作新人操作卡 | 在浏览器或哔哩哔哩定位具体时间点，关联已有知识文档 | 卡片包含可回看的片段，后续修订更新同一文档并保留来源 |
| 下一批 | 用户安排活动，需核对地图、营业时间、团购与预约状态 | 核对门店分店、日期和票种，区分候选方案与已预约记录 | 每个选项附来源及查看时间。预约任务以指定门店和时段的真实回执交付 |
| 首批 | 用户把虚拟电脑上的草稿交给本机，在编辑器改稿后用另一个应用校对 | 由用户在本机为本次任务授权整个桌面，跨应用操作后重新观察 | 核对保存内容，经工作文件回传虚拟设备，并核对撤回授权 |

先练前两项，可以复用一次完整的收件与交付流程。再练 Copilot 改口，把目标变更单独暴露出来。两个场景都稳定后再叠加通知和抢占，便于定位究竟是应用操作、调度还是交付出了问题。

按应用逐一复练。微信、QQ、企业微信和钉钉分别核对群内发件人、附件版本与发送状态。哔哩哔哩与抖音练视频时间点，小红书练原帖和笔记更新，美团练同名分店与有效时段。每种应用独立记录结果。

## 首次演练

在真实 Android 的 EinkBro 下载了一份虚构的活动物料 CSV，DocumentsUI 的下载目录显示 51 字节。通过工作文件复制到 Linux，在 LibreOffice Calc 打开原件，新增短缺列，再另存为 XLSX。横幅需 12、实有 9，胸牌需 40、实有 40。独立读取导出的工作簿，D2、D3 分别保留公式 `B2-C2`、`B3-C3` 和数值 3、0。成品回到手机后，工作区下载内容与手机文件逐字节相同。

演练中，文件复制成功时已打开的手机下载列表仍显示旧内容，重新进入「文件」才看见新工作簿。这条经验已写入 Files 指引。EinkBro 和 DocumentsUI 已接入真实前台包名匹配，同时复用现有的单次 Skill 读取。此次由开发者驱动产品的原生设备工具。下一步用配置好的 Agent 独立完成同一委托，再单独验证真实消息到原会话的交付。

## 如何把演练变成能力

同一任务准备原例及变例，例如列顺序互换、收到修订附件、用户在保存前改口。先留存当前版本的结果，找出第一个选错的对象或缺失的回执，只修改对应应用的指引或工具，再用另一个样本独立重做。可复用的操作方法进入 Skill，项目事实及来源进入关联知识文档。测试样本使用虚构或获准使用的业务数据。

按场景记录成功次数和总次数、首个有效动作、整轮用时、模型调用次数。中断用例另记恢复时长、重复发送与遗漏交付次数。比较时固定模型、设备和任务，并分别记录人工指导与 Agent 独立完成的结果。

## 本机电脑

在共享对话的附件旁打开「本机协作」，选择「允许本次任务」，再发送文字或 Copilot 指令。当前任务可观察整个桌面，在本机应用中点击、滚动、输入和保存。多屏环境按显示器观察和定位。截图会交给当前配置的模型，并保存在本地任务记录。macOS 首次使用需要系统屏幕录制和辅助功能权限。

「结束本机协作」立即关闭这次授权。任务结束或退出客户端后，下次使用时重新授权。虚拟设备的文件经过工作文件中转，主机文件通过用户选择或拖入工作台交接。

在 Mac「预览」打开随机生成的订货单，测试操作者通过 Agent 收到的画面读出订货 87 件、实收 12 件。通过本机工具切到「文本编辑」，输入并保存中文交接稿。独立读回文档，短缺数为 75 件。交接稿进入工作文件和共享对话后，Android 和 Linux 都收到了相同的 67 字节；从助手回复下载的附件也与原件一致。此次使用本机测试适配器。独立在线模型和 Windows 桌面单独验收。

同一份交接稿随后再由 Agent 文件工具分发。同样的两台设备、输入与目的目录，优化前的执行记录有两次读取 GUI 技能、一次手机观察以及两次复制。优化后直接复制两次，再按两个实际目标路径验收并生成回复附件。涉及在应用中编辑的委托继续核对设备画面与操作记录。
